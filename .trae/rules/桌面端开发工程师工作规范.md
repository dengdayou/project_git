## Superpowers 开发原则

> 本节定义桌面端开发工程师必须遵循的Superpowers核心原则，是所有开发活动的最高优先级准则。

### Superpowers 四原则在开发中的体现

| 原则 | 说明 | 在Tauri开发中的具体要求 |
|------|------|----------------------|
| **测试驱动 (TDD)** | 先写测试，再写实现 | Rust: 先写`#[cfg(test)]`，再写`impl`; 前端: 先写Vitest `it()`，再写实现 |
| **系统性优先** | 遵循流程，不靠猜测 | 严格遵循6A工作流 + Tauri开发规范，不跳过任何检查步骤 |
| **简化为上 (YAGNI)** | 简化是首要目标 | 小Command原则：每个Command只做一件事；最小可行功能优先 |
| **证据说话** | 验证后才算完成 | `cargo test`通过 + `vitest`通过 + `cargo clippy`零warning + ESLint零error = 功能完成 |

### ⚡test-driven-development (TDD)

**核心理念**：每个Tauri Command先写测试再写实现，每个前端Composable先写测试再写实现。

```
TDD开发循环（Red → Green → Refactor）：

【Rust后端TDD】
  Step 1 RED：    编写 #[cfg(test)] 测试函数，描述预期行为
  Step 2 GREEN：  运行 cargo test → 确认失败（RED）
  Step 3 GREEN：  编写最少实现代码
  Step 4 GREEN：  运行 cargo test → 确认通过（GREEN）
  Step 5 REFACTOR：运行 cargo clippy → 确认零warning，重构优化
  Step 6 REFACTOR：再次运行 cargo test + cargo clippy → 确认全部通过

【前端TDD】
  Step 1 RED：    编写 Vitest describe/it/expect 测试
  Step 2 GREEN：  运行 npx vitest → 确认失败（RED）
  Step 3 GREEN：  编写最少实现代码
  Step 4 GREEN：  运行 npx vitest → 确认通过（GREEN）
  Step 5 REFACTOR：运行 ESLint + TypeScript 检查，重构优化
  Step 6 REFACTOR：再次运行 npx vitest → 确认全部通过
```

**强制要求**：
- 每个Rust Command必须有对应的`#[cfg(test)] mod tests`测试模块
- 每个前端Composable必须有对应的`.test.ts`测试文件
- 每个Pinia Store必须有对应的`.test.ts`测试文件
- 每个工具函数必须有对应的`.test.ts`测试文件
- 测试覆盖率目标：> 80%

### ⚡systematic-debugging

**4步调试法**：处理Bug时必须遵循的结构化调试流程。

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
🔍 系统化调试 4步法（Tauri桌面端专用）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Step 1：问题定位（Bug Location）
  ├── 复现问题：确定稳定的复现步骤
  ├── 缩小范围：问题在前端？Rust后端？通信层？
  │   ├── 前端问题：检查Vue组件状态、Composable逻辑、路由
  │   ├── Rust问题：检查Command实现、Service逻辑、数据库操作
  │   └── 通信问题：检查Tauri Command参数、返回值序列化
  └── 确定根因：通过日志和断点确认根本原因

Step 2：假设生成（Hypothesis Generation）
  ├── 列出所有可能的原因（至少3个）
  ├── 按概率排序（最可能 → 最不可能）
  └── 为每个假设设计验证方法

Step 3：假设验证（Hypothesis Testing）
  ├── 逐个验证假设（从最可能的开始）
  ├── 使用最小可复现用例验证
  ├── Rust端：使用 dbg! 宏或 log crate 记录日志
  ├── 前端：使用 console.log 或 Vue DevTools 检查状态
  └── 确认根因后，编写回归测试防止复发

Step 4：修复与验证（Fix & Verify）
  ├── 编写修复代码
  ├── 编写或更新对应的测试用例（TDD回归）
  ├── 运行 cargo test + npx vitest 确认全部通过
  ├── 运行 cargo clippy + ESLint 确认零warning
  └── 验证修复不影响其他功能

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### ⚡subagent-driven-development

**核心理念**：Rust后端和前端可以并行开发，通过子代理分工协作提升效率。

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
🤖 子代理并行开发模式（Tauri专用）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

主代理（协调者）
    │
    ├── 子代理A：Rust Commands开发
    │   ├── 任务：实现所有Tauri Commands（TDD模式）
    │   ├── 输入：PRD中的后端接口定义
    │   ├── 输出：src-tauri/src/commands/*.rs + 测试模块
    │   ├── 顺序：RED → GREEN → REFACTOR → cargo test通过
    │   └── 验证：cargo test + cargo clippy 零warning
    │
    ├── 子代理B：前端组件开发
    │   ├── 任务：实现Vue组件和Composables（TDD模式）
    │   ├── 输入：PRD中的前端界面定义 + 设计稿
    │   ├── 输出：src/components/*.vue + src/composables/*.ts + 测试文件
    │   ├── 顺序：RED → GREEN → REFACTOR → vitest通过
    │   └── 验证：npx vitest + ESLint 零error
    │
    └── 子代理C：联调测试（等A、B完成后执行）
        ├── 任务：前后端联调 + 集成测试
        ├── 输入：子代理A和B的产出
        ├── 输出：tests/integration/* 测试文件
        └── 验证：全量测试通过 + 功能验证通过

并行开发约定：
- Rust后端和前端通过Tauri Command接口契约解耦
- 接口契约在开发前定义好（Command名称、参数、返回值类型）
- 各子代理独立开发，互不阻塞
- 联调阶段统一集成验证

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

#### ⚡TDD代码示例（Rust后端）

```rust
// src-tauri/src/commands/file.rs
use tauri::command;
use std::fs;

#[derive(Debug, serde::Serialize)]
pub struct FileInfo {
    path: String,
    content: String,
}

#[command]
pub async fn open_file_dialog() -> Result<Option<FileInfo>, String> {
    let path = rfd::AsyncFileDialog::new()
        .add_filter("Text", &["txt"])
        .add_filter("JSON", &["json"])
        .pick_file()
        .await;
    
    if let Some(file) = path {
        let path_str = file.path().to_string_lossy().to_string();
        let content = fs::read_to_string(file.path())
            .map_err(|e| e.to_string())?;
        Ok(Some(FileInfo { path: path_str, content }))
    } else {
        Ok(None)
    }
}

#[command]
pub async fn save_file_dialog(content: String, filename: String) -> Result<Option<String>, String> {
    let path = rfd::AsyncFileDialog::new()
        .set_file_name(&filename)
        .save_file()
        .await;
    
    if let Some(file) = path {
        fs::write(file.path(), content)
            .map_err(|e| e.to_string())?;
        Ok(Some(file.path().to_string_lossy().to_string()))
    } else {
        Ok(None)
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn test_file_info_struct_creation() {
        let info = FileInfo {
            path: "/test/path.txt".to_string(),
            content: "hello world".to_string(),
```

```typescript
import { invoke } from '@tauri-apps/api/core';

interface FileInfo {
  path: string;
  content: string;
}

export function useFile() {
  const currentFile = ref<FileInfo | null>(null);
  const loading = ref(false);
  const error = ref<string | null>(null);

  const openFile = async (): Promise<FileInfo | null> => {
    loading.value = true;
    error.value = null;
    try {
      const result = await invoke<FileInfo | null>('open_file_dialog');
      if (result) {
        currentFile.value = result;
      }
      return result;
    } catch (e) {
      error.value = typeof e === 'string' ? e : String(e);
      return null;
    } finally {
      loading.value = false;
    }
  };

  const saveFile = async (content: string, filename: string): Promise<string | null> => {
    loading.value = true;
    error.value = null;
    try {
      return await invoke<string | null>('save_file_dialog', { content, filename });
    } catch (e) {
      error.value = typeof e === 'string' ? e : String(e);
      return null;
    } finally {
      loading.value = false;
    }
  };

  return { currentFile, loading, error, openFile, saveFile };
}
```

### 4.4 开发执行7大原则

0. **测试驱动开发 (TDD)**（最高优先级）
   - Rust：先写`#[cfg(test)]`测试，再写实现
   - 前端：先写Vitest测试，再写实现
   - 每个Command必须有测试
   - 每个Composable必须有测试
   - RED → GREEN → REFACTOR循环不可跳过

1. **前端与Rust分离**
   - 前端专注于UI和交互（Vue 3 + Element Plus）
   - Rust专注于系统级功能
   - 通过Tauri Commands通信

2. **Rust代码质量**
   - 使用`cargo clippy`检查代码
   - 错误处理使用`Result<T, E>`
   - 异步操作使用`async/await`

3. **Vue 3最佳实践**
   - 使用Composition API
   - 使用`<script setup>`语法
   - 状态管理使用Pinia
   - 组件使用Element Plus

4. **性能优化**
   - 耗时操作放在Rust端
   - 前端使用虚拟列表、懒加载
   - 利用Vue 3的响应式系统
   - 利用Rust的高性能

5. **安全性**
   - 验证所有Command输入
   - 使用Tauri的权限系统
   - 避免暴露敏感API

6. **跨平台兼容**
   - 使用`std::env::consts::OS`判断平台
   - 平台特定代码使用条件编译
   - 测试覆盖所有目标平台

7. **代码规范**
   - 前端：ESLint + Prettier + Vue官方规范
   - Rust：rustfmt + clippy
   - 函数和结构体必须有文档注释

### Q6：⚡如何进行系统化调试？

**A：** 遵循Superpowers 4步调试法：

```
Step 1 问题定位：
  - 确定问题在前端/Rust后端/通信层中的哪一层
  - 前端问题：检查Vue组件状态、Composable逻辑
  - Rust问题：检查Command实现、Service逻辑
  - 通信问题：检查Command参数、返回值序列化
  - 使用 dbg! 宏（Rust）或 Vue DevTools（前端）定位

Step 2 假设生成：
  - 列出至少3个可能的原因
  - 按概率排序

Step 3 假设验证：
  - 从最可能的原因开始逐个验证
  - 使用最小可复现用例

Step 4 修复与验证：
  - 编写修复代码
  - 编写或更新测试用例防止复发（TDD回归）
  - 运行 cargo test + npx vitest 确认全部通过
```

### Q7：⚡TDD开发中如何处理需要GUI交互的Tauri Command？

**A：** 将GUI交互与业务逻辑分离，业务逻辑部分可以独立测试：

```rust
// 业务逻辑（可独立测试）
fn parse_file_content(content: &str) -> Result<Vec<String>, String> {
    content.lines()
        .map(|line| line.trim().to_string())
        .filter(|line| !line.is_empty())
        .collect::<Vec<_>>()
        .into_iter()
        .map(|line| {
            if line.starts_with('#') {
                Err("Invalid line format".to_string())
            } else {
                Ok(line)
            }
        })
        .collect()
}

// Tauri Command（GUI交互层）
#[command]
pub async fn process_file() -> Result<Vec<String>, String> {
    let path = rfd::AsyncFileDialog::new().pick_file().await;
    match path {
        Some(file) => {
            let content = fs::read_to_string(file.path())
                .map_err(|e| e.to_string())?;
            parse_file_content(&content)
        }
        None => Ok(vec![])
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn test_parse_file_content_valid() {
        let result = parse_file_content("line1\nline2\nline3");
        assert_eq!(result.unwrap(), vec!["line1", "line2", "line3"]);
    }

    #[test]
    fn test_parse_file_content_with_comments() {
        let result = parse_file_content("line1\n#comment\nline3");
        assert!(result.is_err());
    }

    #[test]
    fn test_parse_file_content_empty() {
        let result = parse_file_content("");
        assert_eq!(result.unwrap(), Vec::<String>::new());
    }
}
```
