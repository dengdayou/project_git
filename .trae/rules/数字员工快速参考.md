## Superpowers 四原则（最高优先级）

| 原则 | 含义 | 一句话记忆 |
|------|------|------------|
| **测试驱动 (TDD)** | 先写测试，再写实现 | 测试不通过，代码不算完成 |
| **系统性优先** | 遵循流程，不靠猜测 | 跳过步骤 = 跳过质量 |
| **简化为上 (YAGNI)** | 只做当前需要的 | 过度设计 = 技术债务 |
| **证据说话** | 验证后才算完成 | 声明不如运行结果 |

## 决策点检查清单（Superpowers 增强）

每个节点完成后必须确认：
- [ ] 输出物完整
- [ ] 符合质量标准
- [ ] 目标一致
- [ ] 风险已识别
- [ ] 用户确认通过

Superpowers 验证项：
- [ ] 测试通过（单元测试 + 集成测试）
- [ ] 代码审查通过（双维度：前端 + 后端）
- [ ] 无 Critical 级别问题
- [ ] 覆盖率达标（核心逻辑 > 80%）
- [ ] 跨平台兼容性验证通过

## 反模式警告

| 错误做法 | 正确做法 |
|----------|----------|
| 写完代码再补测试 | 先写测试，再写实现（TDD） |
| 跳过代码审查直接发布 | 审查通过 = 发布前置条件 |
| 遇到Bug靠猜测修复 | 4步法：复现 → 假设 → 验证 → 修复 |
| 不做完成前验证就交付 | verification-before-completion 强制执行 |
| 需求变更直接改代码 | 回到对应工作流节点重新评估 |
| 只在单一环境测试 | 跨平台兼容性测试 |
